# Assumptions

- **A1 — ISB multipart contract is adequate.** Status: VALIDATED. `S3AdapterDataPublisher` read firsthand: direct-to-S3 in-pod client (no middleman/Cloudflare), per-part memory only, atomic Complete (ordered PartETag assembly; object exists only after Complete), Abort exists and swallows its own failures, a failed part does not pollute `session.UploadedParts` (same-part retry is clean), `MaxErrorRetry=3` transient retries under the SDK. Known micro-inefficiency: per-part `data.ToArray()` copy (out of scope).
- **A2 — S3 size laws.** Status: VALIDATED. Part ≤5GiB, ≤10,000 parts, object ≤5TB → ≈48GiB object ceiling at 5MiB parts; single PUT ≤5GB. No practical constraint for this design.
- **A3 — Motivating measurements.** Status: VALIDATED. Tenable production run 20260706-102603: pages avg 8.4MB / max 31.1MB; records avg 579KB / max 17.8MB; fattest single finding 13.6MB; densest asset 842 findings. Fail-fast is one dense+fat asset from a dead run.
- **A4 — Rejected alternatives (decision trail).** Status: VALIDATED (evidence-based rejections). Repeated-host-per-slice: exposure-analytics ingest inserts by parser-minted per-row uuid with generation version-flip — duplicates or churns, never merges. Deterministic UUIDv5 identity: shelved (valuable for cross-run identity; unnecessary once objects aren't size-split). Byte-cap record slicing as the primary fix: demoted to deferred follow-up (Spark line discipline only). Collector-side adoption surgery: deleted — the publish-call boundary already IS the semantic batch boundary.
- **A5 — Exact inventory of dead pre-splitting paths per collector on dev.** Status: OPEN (internal). Must be enumerated from code during execution, not assumed; apply the behaviour-over-shape judgment rule per site.
- **A6 — No consumer depends on multi-object-per-call semantics.** Status: OPEN (internal). Verify `PublishResult`/session consumers and progress-event emitters before deleting rotation branches.
- **A7 — NdjsonContentHasher integration point supports the size extension cleanly.** Status: OPEN (internal). Inspect during execution; hash-identical single-vs-multipart invariant must survive.
- **A8 — 50MiB has no external contract force.** Status: VALIDATED (user-confirmed). "No one cares about the 50MiB limit — it's a conceptual magic number set to prevent pod memory bloat"; the four-layer defense carries the actual memory guarantees.
