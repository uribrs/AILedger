### Design (W1+W2 — correlated Falcon findings rewrite)

Model: asset-driven traversal mirroring `FalconCorrelatedFindingsProbe`. Discover hosts scroll (sort=last_seen_timestamp.asc, filter = user FQL host filter + last_seen>=baseDate) drives the run; prefetch next Discover page before per-page join work; slice each page's aids into batches (AidBatchSize, default 250); one aid-scoped Spotlight scroll per batch (sort=updated_timestamp.asc, one pass, facets cve+remediation(+evaluation_logic), filter not-suppressed + status:['open','reopen','closed'] + updated>=baseDate + aid:[batch]); group each Spotlight page by aid into per-aid accumulators; flush a chunk record at the chunk cap (ChunkFindingsCap, default 2000); at batch end flush remaining accumulators with isLastChunk=true incl. zero-finding hosts. One published `findings_*.json` page per aid batch, streamed to egress (no whole-batch buffering). No assets_*.json lane.

Record: `{aid, chunk, isLastChunk, findingsInChunk, host, findings[]}`; host = verbatim Discover record; findings = verbatim Spotlight records with `apps`/`suppression_info`/`host_info` stripped and `remediation.entities` sorted by serialized form. host_info also dropped as a Spotlight facet.

Cursor discipline: after-tokens never persisted. In-process re-anchor on 404 cursor expiry — Discover from last processed host's last_seen watermark + boundary-aid dedupe; Spotlight from last updated_timestamp + per-batch seen-finding-id dedupe (mirrors prototype). Transport retries stay in DefensiveToolkit; token refresh in CredentialProviderAuthenticator.

Checkpoint (format v2, no cross-version resume): Discover last_seen watermark + boundary aids + output page counter + totals + aidBatchSize (per-batch watermark advance; no per-page offset — see deviations). Written at aid-batch boundaries (the durable boundary). `CanResumeFrom` rejects any checkpoint whose `findingsFormatVersion` != 2 → fresh restart. Base `FalconCheckpointState` + `FalconAssetsCheckpointState` and the whole standalone assets flow (incl. month segments) left untouched.

Retired: status lanes (LaneRunner/StageSequencer/LaneState/LaneFilter/PageCheckpointHandler), FalconSpotlightVulnerabilitiesRunner, AID pre-pass (AidBatchProducer/AssetIdsFetcher), FalconFindingsAssetsStage, FalconFindingsStage, planned yields (FalconPlannedYieldException/Kind + FalconFlowRetryPolicy → UnknownFlowRetryPolicy), FalconCursorSanitizer + ApplyCursorTtlForResume (no persisted cursors), FalconFindingsProgressSnapshot, FalconFindingsRunStats, and the findings DTOs (SpotlightVulnerabilities Run/Request/Result, PublishVulnerabilitiesPageRequest, VulnerabilitiesFetch*, FindingsAidScopedResumeState, FindingsSpotlightYieldState). ### Deviations from the prototype (deliberate)
- Bounded boundary-aid dedupe instead of the prototype's unbounded global `_processedAids` set: the checkpoint/re-anchor dedup only tracks AIDs at the exact `last_seen` watermark boundary (memory-bounded), matching the contract's "processed-aid dedupe at the boundary".
- Per-batch watermark (no per-page aid offset): because a Discover page is chunked into batches in last_seen.asc order, the batch max is monotonic, so the Discover watermark advanced per aid-batch alone locates the resume position. The `CurrentPageAidOffset` field the contract sketched proved unnecessary and was dropped to keep the checkpoint minimal.
- Discover URL reuses the existing assets URL builder (facets risk_factors/third_party/system_insights, last_seen.asc); a new `FalconUrls.BuildCorrelatedSpotlightBaseUrl` drops the host_info facet.
