# Decisions

- Correlated record grammar mirrors Falcon: `{uuid, chunk, isLastChunk, findingsInChunk, host, findings[]}`; 2,000-findings cap per record. (Pinned — proven contract, parser detection generalizes.)
- Asset key field named `uuid` (Tenable's identifier), not Falcon's `aid`. (Provisional — user may override.)
- CollectFindings drops the separate assets lane; correlated envelopes are the asset spine; standalone CollectAssets unchanged. (Pinned — Falcon precedent.)
- `host` = full `/assets/export` record verbatim; no field stripping now. (Provisional — payload trim is a later product decision; spool math does not require it.)
- `num_assets` default lowered 500 → 50, config-overridable. (Provisional — measured chunk p50 22MB / max 43MB at 50.)
- In-RAM spool: `uuid → gzip-compressed raw UTF-8 bytes`, remove-on-use, hard budget default ~1GB compressed (~700K assets at measured density). (Pinned.)
- Budget overflow degrade: publish overflow assets as chunk-0 host records, keep uuid marker set, their findings emit host-less. (Pinned. **AMENDED** in the egress-law adjustment (2026-07-08): overflow hosts are no longer published one-page-at-a-time unannounced — they are buffered during spooling and published as ONE announced batch object, WITH checkpoint + AdvancePage, at the end of the spool phase. Settles the previously-open "never individually announced" wrinkle in Documentation/04. Under the full-re-spool resume model a crash before that publish just re-accumulates; after it, duplicates are absorbed by A9.)
- Miss lane: thin host from the finding's embedded `asset` sub-object; counted + logged; never dropped, never buffered. Unifies orphans, snapshot skew, hypothetical straddles, post-resume gaps. (Pinned.)
- Resume ordering: claimed-set rebuilt FIRST via uuid-only re-scan of processed vuln chunk ids, then spool rebuild skipping claimed. (~~Pinned~~ **SUPERSEDED** in repair round 2 — code review M1. The uuid-only re-scan re-downloaded every processed vuln chunk's full bytes each resume (no uuid projection exists), so resume cost grew with progress and could livelock against the 24h export expiry. New behavior: resume does NO claimed rebuild — it re-spools the FULL assets export and re-sweeps the full residue; assets emitted before the crash re-emit as duplicate empty-findings envelopes, absorbed by parser per-UUID aggregation (A9). Rationale: bandwidth livelock > RAM savings, and the spool budget already bounds RAM.)
- Windowed-join mode is documented as the escape hatch behind the spool abstraction; NOT implemented now. (Pinned — YAGNI until a tenant exceeds the budget.)
- Both exports created up front (concurrent server-side generation). (Pinned — free pipelining, limit is 10.)
- Checkpoint format version bump + MAJOR CollectorVersion bump. (Pinned — architectural output-contract change.)
- Zero-vuln sweep runs only after all vuln chunks complete (asset-partitioning makes absence global). (Pinned.)
- Rollout ordering (cross-repo): the later-phase parser ships before this collector reaches production — same parser-first strategy as Falcon. (Pinned — out of this task's scope but recorded.)

### Egress-law adjustment (2026-07-08)

- **One publish call = one atomic, size-unbounded object.** The dev merge brought the shared egress law (`DataPipeline/Egress/README.md`): each `PublishAsync` materializes exactly one object, streamed to storage as multipart under the hood, with no per-record/per-object size cap. The collector's `TenableIoCorrelatedPagePublisher` byte-budget pagination is DELETED — one vuln chunk → one `findings_*.json` object; the spool-overflow buffer → one object; the sweep → one object. The "page counter" is now a batch counter (one increment per publish). (Pinned by the team lead.)
- **`isFinalPage` seam REMOVED — SUPERSEDES the repair-round-2 M3 decision.** With one object per chunk there are no non-final pages: `buildCheckpoint` loses the `isFinalPage` parameter and the chunk always joins `processedTenableChunkIds` on its single object's checkpoint (still written after the upload succeeds). Same durability guarantee (chunk marked processed only after its object is up), fewer moving parts.
- **Overflow announcement — SETTLED (see the amended overflow bullet above).**
- **Sweep publishes as one atomic object.** The size-flushing loop is removed; the whole zero-vuln residue is one object. C7 (mid-sweep re-sweep on resume) still holds and is now cleaner (atomic object → publishes fully or not at all).
- **No additional version bump.** `CollectorVersion` stays `5.0.0` and the checkpoint format stays v2 — this adjustment is part of the same unreleased 5.0.0 correlated rewrite and does not change the checkpoint fields, only object granularity. (Pinned.)
- **Peak-RAM trade-off accepted (Documentation/03 C10).** Overflow and sweep buffer their whole batch uncompressed in RAM before the single publish (bounded by the spool budget for the sweep; unbounded in principle for overflow once the compressed budget is full). Streaming-publish escape hatch deferred (YAGNI until a tenant proves the peak matters). (Pinned by the team lead's explicit "buffer … publish as ONE object" instruction.)
