# Decisions

- The budget bounds **consecutive no-progress** deferred recoveries, not total lifetime recoveries. Counter is reinterpreted as `consecutiveNoProgressRecoveryCount`.
- Anchor is a **durable progress coordinate**, not raw `CurrentPage`. Raw `CurrentPage` is poisoned by the defer's own `AdvancePage(0,0)`.
- Coordinate = the host-restored progress counters only — the plain culture-invariant string `"{CurrentPage}:{ProcessedItems}:{ProcessedFindings}"`. NOT a hash of `AdapterState` (the original plan): code review (B1) found the host restores these counters on resume via `RestoreProgress` but does NOT restore business `AdapterState`, so a coordinate hashed over `AdapterState` is incomparable across the resume hop and fails the stuck gate open. Counters are the single restored-and-comparable progress signal; under Path B `CurrentPage` advances only on real committed pages, so they capture all checkpointed progress.
- **Path B (operator decision):** the per-defer page bump is self-inflicted by the resilience defer using `AdvancePage(0,0)`. Fixed by snapshotting via `OnCheckpoint?.Invoke` (mirroring `FalconFindingsCheckpointWriter`) — no page bump. This makes `CurrentPage` a trustworthy progress signal AND stops every collector's reported page count from inflating on every deferred wait (a latent global bug). ISB continues to consume `CurrentPage`, so making it accurate is a net fix. Verified against SDK+ISB source that the bump otherwise persists across the resume hop.
- `CurrentPage` is part of the counter coordinate (safe under Path B — a wait no longer bumps it). It captures empty-page progress: an all-filtered page still calls `AdvancePage`, so `CurrentPage` advances and the coordinate changes.
- **Budget gate has ONE owner: the executor.** Code review (P1) found the policy layer (`MappedFailurePolicy`, `UnknownFlowFailurePolicy`) ALSO gated on the raw attempt count (`RetryAttemptNumber < MaxRetries`) before producing the deferred-recovery decision — short-circuiting to `PublishFailure`/`Rethrow` at the `MaxRetries` boundary before the executor's progress-aware reset could run (re-introducing the original bug at the exact boundary). Removed both policy count-gates: policies now always emit deferred recovery when a retryable backoff is configured, and the executor's `EvaluateBudget` owns reset/increment/fallback. `UnknownFlowFailurePolicy` emits `RecoverAndRetry` with a `RethrowForUnknownRetry` fallback so its exhaustion-rethrow (host-redelivery) semantics are preserved. `AdapterFailureContext.RetryAttemptNumber` is now vestigial (set but unused for gating) — candidate for removal in a follow-up.
- Prior budget is read by the executor from `AdapterState`; the resume leg seeds `_resilience.*` from the restored checkpoint (`CollectorResumeSetup`). Safe because the executor runs once per invocation (the in-runner self-heal is a `continue` loop, not an executor call), so the read equals the flow-start budget — no in-process accumulation.
- `progressed` = (no prior coordinate) OR (coordinate changed). progressed → count = 1; else → count = prevCount + 1. Reset to **1**, not 0 (this defer is attempt #1 of the new episode).
- Stuck gate trips when candidate count **>** `MaxRetries` (so `MaxRetries=3` allows attempts 1,2,3; the 4th consecutive no-progress defer falls back).
- Backstop is whole-collection, never reset by progress, only cleared on full-scan success. OR-combined: total budgeted deferrals > 50 **or** age since first budgeted defer > 24h. First to trip wins. Both configurable.
- Backoff delay indexes off the reset-aware count, so progress also resets the wait sequence to the first step. This incidentally fixes the prior delay-inflation symptom.
- Adaptive control state in `AdapterState` (e.g. Qualys `MaxConcurrency`) is irrelevant to the coordinate by construction — the coordinate is counters-only and never reads `AdapterState`. (Earlier concern moot after the B1 simplification.)
- Failure-type partitioning is explicitly NOT done. Progress is the universal signal; any failure that lets the scan advance resets the count.
- Migration: missing coordinate on load → treated as progress → count = 1. Graceful, slightly lenient at the upgrade boundary; accepted.
