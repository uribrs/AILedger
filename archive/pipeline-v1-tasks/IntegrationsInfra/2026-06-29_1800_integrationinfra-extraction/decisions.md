# Decisions (established this session — inputs, not to be re-debated)

- **D1:** Dependency graph is acyclic and safe. `Shared → {Cymulate.Integration.Sdk v3.2.0 (self-contained adapter-contracts SDK from the IntegrationServiceBus repo; deps only MS.Extensions.{DI,Logging}.Abstractions + Polly), Cymulate.Http.Package.Session v2.0.2}`. The bus host loads adapters as runtime plugins (`deps.json` closure), not a compile reference. No circular dependency; no dependency surgery needed.
- **D2:** Target topology mirrors the IntegrationServiceBus split — (1) IntegrationInfra **Abstractions/facade** package = the capability bank contract (single entry; small set of cohesive capability groups e.g. Transport/Session, Egress, Resilience, Recovery, Envelope; plus a top-level compose-and-run entry); (2) IntegrationInfra **mechanics** package implementing it; (3) a REAL composition/runtime layer in the adapters repo, renamed away from "Orchestration". CollectorExecutor is the working prototype of that composition layer.
- **D3:** Single ENTRY, not a single mega-interface. Graduated power: declarative compose-and-run (top), capability groups (middle), raw building blocks (bottom, for control-heavy adapters) — all via ONE handle. Avoid a god-object facade.
- **D4:** No external consumers are waiting → no backward-compat burden → author the contract fresh; do NOT preserve the existing wide surface.
- **D5:** "Orchestration" today is name-only call-helpers, NOT a composition layer; adapters currently bind wide and directly into mechanics internals (import sites: Orchestration 182, Session 136, Events 130, Glossary 122, Resilience 65, DataPipeline 62, Recovery 36; 10 public interfaces vs 136 public classes).
- **D6:** Complete-vs-hybrid is the spine: incomplete concepts get reconsidered (rework/drop/defer), never enshrined as SDK contracts.
